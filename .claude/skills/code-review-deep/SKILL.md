# ダブルチェック・コードレビュー

2つの独立したサブエージェントに並列でレビューさせ、結果を統合することで見落としを減らす。

## 手順

### ステップ1: レビュー対象の特定

ユーザが指定したファイル、差分、またはPRの変更内容を特定する。
対象が不明な場合は `git diff` や `git diff --staged` で差分を取得する。

$ARGUMENTS が指定されている場合はそれをレビュー対象とする。

### ステップ2: 2つのサブエージェントを並列起動

Taskツールを使い、以下の2つのエージェントを **必ず同時に（1つのメッセージで）** 起動する。
それぞれ異なる視点でレビューさせることが重要。

#### エージェントA: ロジック・正確性レビュアー

subagent_type: `general-purpose` で起動し、以下のプロンプトを渡す:

```
あなたはコードレビュアーAです。ロジックの正確性と堅牢性の観点でレビューしてください。

レビュー対象: {対象ファイルまたは差分の情報}

以下の観点で徹底的にチェックし、問題点をすべて列挙してください:

1. **正確性**: 条件分岐の漏れ、オフバイワンエラー、型変換の問題
2. **エラーハンドリング**: 例外の握りつぶし、リソースリーク、異常系の考慮漏れ
3. **データ整合性**: トランザクション境界、競合状態、デッドロック、中途半端な状態の残存
4. **境界値**: null/undefined/空文字列/空配列/0件/最大件数の考慮

「問題なさそう」と思った箇所こそ疑いの目で見直してください。
各指摘は [MUST]/[SHOULD]/[IMO] の重要度を付けてください。

出力形式:
### [重要度] 指摘タイトル
- **ファイル**: ファイルパス (行番号)
- **内容**: 問題点
- **理由**: なぜ問題か
- **修正案**: 具体的な修正方法
```

#### エージェントB: セキュリティ・設計レビュアー

subagent_type: `general-purpose` で起動し、以下のプロンプトを渡す:

```
あなたはコードレビュアーBです。セキュリティと設計品質の観点でレビューしてください。

レビュー対象: {対象ファイルまたは差分の情報}

以下の観点で徹底的にチェックし、問題点をすべて列挙してください:

1. **セキュリティ**: SQLインジェクション、XSS、パストラバーサル、認証認可の漏れ、CSRF、機密情報の露出
2. **入力バリデーション**: 外部入力（画面、API、ファイル）の検証不足
3. **パフォーマンス**: N+1クエリ、ループ内DB/API呼び出し、メモリ圧迫
4. **設計・保守性**: 責務分離、命名の適切さ、コードの重複、ネストの深さ

「問題なさそう」と思った箇所こそ疑いの目で見直してください。
各指摘は [MUST]/[SHOULD]/[IMO] の重要度を付けてください。

出力形式:
### [重要度] 指摘タイトル
- **ファイル**: ファイルパス (行番号)
- **内容**: 問題点
- **理由**: なぜ問題か
- **修正案**: 具体的な修正方法
```

### ステップ3: 結果の統合

両エージェントの結果を受け取ったら、以下の手順で統合する:

1. **重複の排除**: 同じ箇所に対する同じ指摘はマージする
2. **重要度の調整**: 両方が指摘した項目は重要度を上げることを検討する
3. **観点の補完**: 片方だけが見つけた指摘も漏らさず含める
4. **統合レビューとして最終出力する**

### 出力フォーマット

```
## ダブルチェック・レビュー結果

- MUST: X件
- SHOULD: X件
- IMO: X件
- （両エージェント共通指摘: X件）

## 指摘事項

### [MUST] 指摘タイトル
- **ファイル**: `path/to/file` (L42-L50)
- **検出**: A / B / 共通
- **内容**: 具体的な問題点の説明
- **理由**: なぜ問題なのかの説明
- **修正案**: 具体的な修正方法の提示

...

## 良い点
変更の中で特に良い点があれば記載する
```

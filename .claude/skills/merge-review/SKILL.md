# マージレビュー

PR/MRをマージして良いかを総合的に判断するレビュー。
コード品質のチェックに加え、マージ特有のリスク（コンフリクト、CI、マイグレーション、環境設定、デプロイ影響）を確認する。

## レビューの進め方

1. PR/MRの概要を把握する（タイトル、説明、関連issue）
2. 変更の全体像を確認する（変更ファイル数、差分の規模）
3. 以下のチェック観点に沿ってレビューする
4. **セルフダブルチェック**: 「問題なし」と判断した箇所を疑いの目で再確認する
5. マージ可否の判定を出す

## 指摘の重要度

- 🔴 **[MUST]** マージブロック。この指摘が解消されるまでマージ不可
- 🟡 **[SHOULD]** マージ可だが対処推奨。可能ならマージ前に修正、難しければissue化して追跡
- 🟢 **[IMO]** 提案。マージには影響しない改善案

## チェック観点

### 1. PR/MRの形式・粒度

- PRの説明が変更内容を十分に説明しているか
- 変更の粒度は適切か（巨大PRになっていないか、無関係な変更が混入していないか）
- コミット履歴は論理的にまとまっているか

### 2. コード品質（code-review skillの観点）

以下は簡潔にチェックする。詳細レビューが必要な場合は `/code-review` または `/code-review-deep` の使用を推奨する。

- 正確性: 条件分岐の漏れ、境界値、null考慮
- セキュリティ: インジェクション、XSS、認証認可、機密情報
- エラーハンドリング: 例外の握りつぶし、リソースリーク
- パフォーマンス: N+1、ループ内I/O

### 3. マイグレーション・DB変更

- DBスキーマ変更がある場合:
  - マイグレーションは既存データを壊さないか
  - ロールバック手順はあるか
  - カラム追加時のデフォルト値は適切か
  - 大規模テーブルへのALTERによるロック影響はないか
- マスタデータの変更がある場合:
  - 環境差異（開発/ステージング/本番）を考慮しているか

### 4. 設定ファイル・環境変数

- 設定ファイル（application.yml、.env等）の変更はあるか
- 新しい環境変数が追加されている場合:
  - 各環境での設定値は準備されているか
  - デフォルト値は安全か
  - 機密値がコードにハードコードされていないか
- feature flagの追加・変更はあるか

### 5. 依存関係・ライブラリ

- 新しい依存ライブラリが追加されていないか
- 追加されている場合:
  - ライセンスは問題ないか
  - 既知の脆弱性はないか
  - メンテナンスされているライブラリか

### 6. 後方互換性・デプロイ影響

- API仕様の変更がある場合:
  - 既存クライアントへの影響はないか
  - バージョニングは適切か
- バッチ処理の変更がある場合:
  - 実行中のジョブへの影響はないか
  - スケジュール変更は関係者に共有されているか
- デプロイ順序の制約はないか（DB先 → アプリ後、など）

### 7. テスト

- 変更に対応するテストが追加・更新されているか
- CIが通っているか（テスト、lint、ビルド）
- テストカバレッジが低下していないか

### 8. ブランチ・コンフリクト

- マージ先ブランチとのコンフリクトはないか
- マージ先の最新変更を取り込んでいるか
- 他のPR/MRとの競合リスクはないか（同じファイルを変更している等）

## マージ可否の判定

すべてのチェックを終えた後、以下のいずれかの判定を出す:

- ✅ **マージ可**: 問題なし、またはIMOレベルの指摘のみ
- ⚠️ **条件付きマージ可**: SHOULDレベルの指摘あり。対応方針の確認後にマージ推奨
- ❌ **マージ不可**: MUSTレベルの指摘あり。修正が必要

## レビュー結果の出力フォーマット

以下の形式でレビュー結果を出力する:

```
## マージレビュー結果

### 判定: ✅ マージ可 / ⚠️ 条件付きマージ可 / ❌ マージ不可

### PR概要
- **タイトル**: PRタイトル
- **変更規模**: X files, +Y/-Z lines
- **対象ブランチ**: feature/xxx → main

### サマリ
- 🔴 MUST: X件
- 🟡 SHOULD: X件
- 🟢 IMO: X件

## 指摘一覧

| # | 重要度 | カテゴリ | ファイル | 行 | 指摘内容 |
|---|--------|----------|----------|----|----------|
| 1 | 🔴 MUST | セキュリティ | `path/to/file.java` | L42 | 指摘タイトル |
| 2 | 🟡 SHOULD | DB変更 | `migration/V2.sql` | L5 | 指摘タイトル |
| 3 | 🟢 IMO | 可読性 | `Service.java` | L88 | 指摘タイトル |

## 指摘詳細

### 1. 🔴 指摘タイトル
- **カテゴリ**: セキュリティ
- **ファイル**: `path/to/file.java` (L42)
- **内容**: 具体的な問題点の説明
- **理由**: なぜ問題なのかの説明
- **修正案**: 具体的な修正方法の提示

...

## マージ前の確認事項
マージ前に確認・対応が必要な事項をチェックリストで記載する:
- [ ] 確認事項1
- [ ] 確認事項2

## 良い点
変更の中で特に良い点があれば記載する
```
